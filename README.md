# PaySafe — Blockchain-Based Prepaid Consumer Protection

FTEC5520A Applied Blockchain and Cryptocurrencies — final project demo.

A consumer prepays **HK$6,000 for 12 sessions**. The money does **not** go to the merchant.
It is held in a smart contract and released **HK$500 at a time** as sessions are actually consumed.
If the merchant closes down before the package is used up, the remaining balance goes back to the consumer.

The demo exists to show one thing: **a smart contract can stop a merchant from touching prepaid money it has not earned yet.**

---

## 1. How it works

```
Consumer pays HK$6,000
        │
        ▼
┌─────────────────────────────┐
│  PrepayVault (escrow)       │   HK$6,000 locked
│  releasedAmount = 0         │
└─────────────────────────────┘
        │  useSession() × 3   (bookkeeping only — no transfer)
        ▼
  releasedAmount = HK$1,500      protected = HK$4,500
        │
        ├── merchant withdraws ≤ HK$1,500   ✅
        ├── merchant tries HK$4,500         ❌ "Reserve funds are locked."
        │
        ▼  regulator marks merchant closed
  refund = totalPaid − releasedAmount = HK$4,500 → consumer
  second refund attempt                ❌ "Refund has already been processed."
```

The important design point: **`useSession()` never moves money.** It only increments a counter.
The merchant's withdrawable balance is computed as `releasedAmount - withdrawnAmount`, so
"unearned money" is not protected by a rule that could be bypassed — there is simply no
balance to withdraw.

### Demo money model

No real HKD is involved. Amounts are simulated in wei with a fixed rate:

| Concept | Value |
|---|---|
| 1 HKD | `1e15` wei (0.001 ETH) |
| Price per session | `500e15` wei = 0.5 ETH |
| Package (12 sessions) | `6000e15` wei = 6 ETH |

The UI divides by `1e15` and displays HK$ values.

### Roles

| Role | Hardhat account | Can do |
|---|---|---|
| Regulator | `accounts[0]` | license / revoke a merchant, mark it closed, process refunds |
| Merchant | `accounts[1]` | withdraw released funds only |
| Consumer | `accounts[2]` | buy the package, use sessions |

## 6. The 3-minute demo route

| Step | Page | Action | Expected result |
|---|---|---|---|
| 1 | Regulator | **Register Merchant** | `Merchant registered successfully.` / License: **Licensed** |
| 2 | Consumer | **Buy Package** | `Package purchased successfully.` / Total Paid HK$6,000, Protected HK$6,000, Reserve Ratio 100% |
| 3 | Consumer | **Use One Session** × 3 | Sessions 3/12, Released HK$1,500, Protected HK$4,500, Reserve Ratio 75% |
| 4 | Merchant | **Test Excess Withdrawal** | `Transaction Failed` / `Reserve funds are locked.` / `The merchant cannot withdraw unused consumer funds.` |
| 5 | Merchant | **Withdraw Available Funds** | `Withdrawal successful.` / `Amount: HK$1,500` |
| 6 | Regulator | **Mark Merchant as Closed** | `Merchant has been marked as closed.` |
| 7 | Regulator | **Process Consumer Refund** | `Consumer refund processed successfully.` / `Refund Amount: HK$4,500` |
| 8 | Regulator | **Process Consumer Refund** again | `Transaction Failed` / `Refund has already been processed.` |

The **Activity Log** page replays every step from on-chain events.

> **Two clicks for irreversible actions.** *Mark Merchant as Closed*, *Process Consumer Refund*
> and *Revoke Merchant License* ask for confirmation first — the first click only shows
> "Click … once more to confirm". This applies to step 8 as well: two clicks to see the rejection.

Pages can also be opened directly: `http://localhost:8501/?page=Merchant`

A word-for-word presenter script with timings is in [`docs/DEMO_SCRIPT.md`](docs/DEMO_SCRIPT.md).

### Reset before a live demo

State lives on the local chain, so restart the node and redeploy:

```bash
# Ctrl-C in terminal 1, then
npx hardhat node
# terminal 2
npx hardhat run scripts/deploy.js --network localhost
```

Then reload the browser tab.

### c) End-to-end UI verification

Drives the real `frontend/app.py` through Streamlit's AppTest harness — clicking the same
buttons a presenter would click, against the running node.

```bash
# needs terminal 1 (node) and a freshly deployed chain
cd paysafe
source .venv/bin/activate
python scripts/verify_ui.py
```

`verify_ui.py` runs with `PAYSAFE_NO_CONFIRM=1` so each step is a single click.

### d) Confirmation gate (two-click actions)

```bash
cd paysafe
source .venv/bin/activate
python scripts/verify_confirm.py
```

Checks that one click on *Revoke Merchant License* only asks for confirmation and changes
nothing, and that the second click actually goes through. Uses revoke because it can be undone,
so the chain is left as it was found.

## 8. Contracts

### MerchantRegistry

| Function | Who | Effect |
|---|---|---|
| `registerMerchant(address)` | regulator | licenses a merchant |
| `revokeMerchant(address)` | regulator | removes the license |
| `isLicensed(address) → bool` | anyone | current license status |

### PrepayVault

| Function | Who | Effect |
|---|---|---|
| `buyPackage(address merchant) payable` | consumer | locks HK$6,000; requires a licensed merchant and exactly `PACKAGE_PRICE` |
| `useSession(uint256 id)` | consumer | `sessionsUsed += 1`, `releasedAmount += HK$500`; max 12 |
| `withdrawReleasedAmount(uint256 id, uint256 amount)` | merchant | reverts unless `amount ≤ releasedAmount − withdrawnAmount` |
| `markClosed(uint256 id)` | regulator | opens the refund path, blocks further sessions |
| `refundUnusedBalance(uint256 id)` | regulator | pays `totalPaid − releasedAmount` back; only once |
| `getPackage(uint256 id)` | anyone | full package state |
| `availableToWithdraw(uint256 id)` | anyone | withdrawable right now |
| `protectedBalance(uint256 id)` | anyone | consumer money still in escrow |
| `previewRefund(uint256 id)` | anyone | refund amount if closed now |

### Failure cases enforced on-chain

| Case | Trigger | Revert reason |
|---|---|---|
| 1. Excess withdrawal | merchant withdraws more than released | `Reserve funds are locked.` |
| 2. Unlicensed merchant | purchase against an unregistered merchant | `Merchant is not licensed.` |
| 3. Double refund | second refund after a successful one | `Refund has already been processed.` |

## 9. Scope notes

Deliberately out of scope (per the project brief): oracles, Chainlink, NFTs, DAOs, zero-knowledge
proofs, public testnets, real HKD payments, multiple package types, arbitration, databases and
login systems. Everything runs offline against a local Hardhat node — no external API is called.
